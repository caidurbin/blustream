# Control4 driver: TCP on port 8000 instead of telnet:23

The driver connects on the device's port **8000** (raw TCP) rather than the documented default port 23 (telnet). Port 23 performs telnet IAC negotiation (DO/WILL escape codes on connect) which complicates Lua parsing; port 8000 is raw text command/response, much cheaper to write a Lua client against. Concurrent multi-client TCP works on the DMP168, so port 23 stays available for ad-hoc telnet tools. Consequently, port 8000 is canonical only for the Lua driver (and is what `spec/protocol.yaml`'s `default_port` / generated `DEFAULT_PORT` means); the Python library, CLI, and HA integration deliberately default to 23 via telnetlib3, which handles the IAC negotiation.
