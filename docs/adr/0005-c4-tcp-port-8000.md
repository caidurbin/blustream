# Control4 driver: TCP on port 8000 instead of telnet:23

The driver connects on the device's port **8000** (raw TCP) rather than the documented default port 23 (telnet). Port 23 performs telnet IAC negotiation (DO/WILL escape codes on connect) which complicates Lua parsing; port 8000 is raw text command/response, much cheaper to write a Lua client against. Concurrent multi-client TCP works on the DMP168, so port 23 stays available for the Python CLI, future HA integration, and ad-hoc telnet tools.
