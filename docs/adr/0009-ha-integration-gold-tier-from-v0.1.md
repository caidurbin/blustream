# HA integration: gold-tier quality from v0.1 (POC narrows entity count, not scaffolding)

The first published version of the Home Assistant integration ships a single entity (the uptime sensor) but every supporting surface — config flow, DHCP + zeroconf discovery, reconfiguration flow, diagnostics, repair issues, translations, device registry, runtime data, stale-device handling — is built to the HA Integration Quality Scale **Gold** standard from day one. The POC narrows what we ship (one entity, no writeable controls); it does not narrow how we build it. Adding further entities (volume, mute, routing, presets) in later versions is purely additive — no scaffolding catch-up required. Rationale: retrofitting translations, diagnostics, and reconfiguration is materially more painful than greenfield because it requires auditing existing surfaces rather than designing new ones; the single-entity surface lets every Gold rule be exercised end-to-end without scope-creep on entity count; and the integration's first reviewer (HA core or HACS quality scale) sees a coherent picture rather than a "to be promoted later" disclaimer. **Platinum** is reachable as a stretch goal — the `blustream` library is already async-native (satisfying `async-dependency`, the usual blocker), leaving only `strict-typing` and a couple of minor rules — but is not committed until v0.1 ships and the marginal cost is concretely measurable.
