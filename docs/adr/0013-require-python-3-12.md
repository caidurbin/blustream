# Require Python >=3.12 (drop 3.9-3.11)

The `blustream` library now requires **Python >=3.12** (was `>=3.9`), dropping 3.9, 3.10, and 3.11. The forcing function was a dev-toolchain security alert: pytest's tmpdir-handling vulnerability (GHSA-6w46-j5rx-g56g, CVSS 6.8) is fixed only in **pytest 9.0.3**, which itself requires Python >=3.10 with no 8.x backport. While the library still supported 3.9, uv could only resolve the vulnerable pytest 8.4.2 for the 3.9 split, and a flat `pytest>=9.0.3` floor made `uv lock` unsatisfiable. Raising the floor removes pytest 8.4.2 from `uv.lock` entirely, resolving the alert at the dependency level rather than dismissing it — and drops the now-unneeded 3.9 backport shims (`backports-asyncio-runner`, `exceptiongroup`, `tomli`) from the lock as a side effect.

**Why 3.12 specifically — not 3.10, not 3.14.** Python 3.9 reached end-of-life on 2025-10-31. Home Assistant Core — the runtime for the integration artifact (ADRs 0009-0012) — requires **Python >=3.14.2** as of HA 2026.3 (HA architecture ADR-0002 pins HA's floor to the penultimate upstream minor and supports only the latest two minors). So 3.9-3.11 support bought nothing for the library's primary consumer; the integration always runs on a far newer interpreter. We chose **3.12** rather than the minimal CVE-clearing 3.10 (3.10 is itself near EOL, Oct 2026) so the floor lands on a Python with a long support window (3.12 EOL ~Oct 2028); and rather than matching HA's bleeding-edge 3.14 so standalone-CLI consumers on a current-but-not-newest interpreter aren't dragged onto HA's cadence. The CI test matrix moves to **3.12 / 3.13 / 3.14** — floor, middle, and HA's actual runtime — and all 309 tests pass on each.

**Scope and consequences.** This is a breaking change to the library's published support matrix: consumers on 3.9-3.11 must upgrade. Acceptable because those versions are EOL or near-EOL and the library is pre-1.0 (`Development Status :: 3 - Alpha`). The vulnerable dependency is dev/build-only — pytest is never in the shipped wheel, which carries only `blustream/` plus the `telnetlib3` runtime dep (ADR 0008) — so this never affected installed users; it was a supply-chain hygiene fix for the test toolchain. Deferred to a dedicated `style:` commit: bumping ruff `target-version` from `py39` to `py312` and the resulting `X | None` (UP045) modernization across ~52 sites, kept out of this change to keep the security/floor diff reviewable.
